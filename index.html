Fogalomtár

API

Az API egy angol kifejezés rövidítése, ami magyarul „alkalmazásprogramozási felület"-et jelent. Az API-k a szoftverfejlesztők munkáját hivatottak megkönnyíteni azzal, hogy hozzáférést biztosítanak egy adott szoftver vagy eszköz utasításkészletéhez.

REST-API

A REST-API magyarul "Állapotátadásos alkalmazásprogramozási felület" néven ismert. Ez egy olyan API típus, amelyet állapotmentességre terveztek, és az alapvető HTTP módszerekre (GET, POST, PUT, DELETE) támaszkodik a kommunikáció során. Az átláthatóság, megbízhatóság és skálázhatóság elvein működik. A REST API-kat általában webfejlesztésben használják, hogy lehetővé tegyék a kommunikációt különböző rendszerek vagy szolgáltatások között az interneten keresztül.

Általában az API-okról

Mit jelent az API?

Az API rövidítése az Application Programming Interface kifejezésből származik. Ez egy olyan szoftverkomponens vagy rendszer által biztosított interfész, amely lehetővé teszi más szoftverek számára, hogy kommunikáljanak vele, lekérdezzenek vagy módosítsanak adatokat, és meghívjanak funkciókat.

Minden API tartalmaz standardizált protokollokat, adatstruktúrákat és parancsokat, amelyek lehetővé teszik a fejlesztők számára, hogy könnyen integrálják saját alkalmazásaikat más alkalmazásokkal vagy szolgáltatásokkal. Ezek lehetnek webes API-k (HTTP alapú kommunikációval), operációs rendszer API-k (például a Windows API), adatbázis API-k vagy más specifikus funkciókat nyújtó interfészek.

Az API-k létrehozása és használata révén a fejlesztők könnyen bővíthetik vagy integrálhatják alkalmazásaikat más rendszerekkel, szolgáltatásokkal vagy hardverekkel, anélkül hogy mélyebben meg kellene ismerniük az adott rendszer vagy szolgáltatás belső működését.

Például, ha egy időjárás alkalmazást fejlesztünk, akkor az API interfész használatával könnyen tudunk információkat lekérdezni a különböző időjárási adatokról, például hőmérséklet, páratartalom vagy csapadék mennyisége.

Egy másik példában az is API használatnak minősül, ha egy alkalmazásban megjelenítünk egy YouTube videót vagy egy térképet, amelyet az API-n keresztül kapunk megjelenítésre.

Hol használják az API-kat?

Webfejlesztés

Az API-k elengedhetetlenek a webfejlesztés terén. A webes API-k segítségével az online alkalmazások könnyen kommunikálhatnak más rendszerekkel, adatokat kérhetnek le, illetve funkciókat hívhatnak elő. Példák erre a területre a RESTful API-k (REST-API), amelyek segítenek az adatok cseréjében a szerver és a kliens között.

Mobil alkalmazások

Kulcsfontosságúak az API-k a mobil alkalmazások fejlesztésében. Az olyan mobilos operációs rendszerek, mint az iOS vagy az Android, számos API-t nyújtanak a fejlesztőknek, hogy hozzáférjenek a platform-specifikus funkciókhoz és szolgáltatásokhoz (pl. telefonkönyv, helymeghatározás, push-értesítések).

Felhőszolgáltatások

A felhőalapú szolgáltatások széles körben használnak API-kat a funkcióikhoz és adatszolgáltatásukhoz. Például az Amazon Web Services (AWS) vagy az Azure olyan API-kat nyújtanak, amelyekkel a fejlesztők könnyedén hozzáférhetnek az adatbázisokhoz, az adattároláshoz, gépi tanuláshoz vagy számítási erőforrásokhoz a felhőben.

Pénzügyi szektor a közösségi médiában és e-kereskedelemben

A közösségi média platformok, mint például a Facebook, Twitter vagy LinkedIn, szintén API-kat kínálnak a fejlesztőknek. Továbbá az API-k forradalmasítják a pénzügyi szektor működését. A pénzügyi API-k lehetővé teszik a bankok, pénzintézetek és fintech vállalkozások számára, hogy biztonságosan megosszák és cseréljék az adatokat, kezeljék a tranzakciókat.

Az e-kereskedelmi platformok és fizetési rendszerek szintén API-kat használnak a tranzakciók kezeléséhez és az adatok biztonságos átadásához. Ez egy kulcsot ad a fejlesztők kezébe ahhoz, hogy integrálják az alkalmazásaikat az online fizetési rendszerekkel (pl. PayPal, Stripe), és biztosítsák a zavartalan fizetési folyamatot a felhasználók számára.

Alkalmazások közti kommunikáció

De az API-k megkönnyítik az eszközök és alkalmazások közötti kommunikációt és adatcserét is. Az utazási és szállítási alkalmazásokban az API-k nagyban hozzájárulnak az integrációhoz és a szolgáltatások összekapcsolásához. API felhasználásával a fejlesztők integrálják a repülési, szállodai vagy közlekedési szolgáltatásokat az alkalmazásaikba, és elérhetővé teszik a felhasználók számára a foglalásokat, utazási információk lekérdezését vagy a menetrendek megtekintését.

Representational State Transfer (REST)

A Representational State Transfer (REST) egy architekturális stílus, amely meghatározza egy készlet korlátozást a webes szolgáltatások létrehozásához. A REST API egy egyszerű és rugalmas módszer a webes szolgáltatások elérésére anélkül, hogy bármilyen feldolgozást végeznénk.

Hogyan működik?

Egy kérés kerül elküldésre a kliensről a szerverre egy webes URL formájában HTTP GET vagy POST vagy PUT vagy DELETE kérés formájában. Ezután a válasz érkezik vissza a szerverről egy erőforrás formájában, ami bármi lehet, mint HTML, XML, kép vagy JSON. De manapság a JSON a legnépszerűbb formátum a webes szolgáltatásokban.

RESTful Szolgáltatásokhoz HTTP Metódusok használata

  • GET: A HTTP GET metódust arra használjuk, hogy egy erőforrás reprezentációját olvassuk (vagy lekérjük). Biztonságos esetben a GET XML vagy JSON reprezentációt ad vissza és HTTP válaszként a 200-as (OK) HTTP válaszkódot. Hiba esetén leggyakrabban 404-et (NEM TALÁLT) vagy 400-at (ROSSZ KÉRELEM) ad vissza.
  • POST: A POST igét leggyakrabban új erőforrások létrehozására használják. Különösen arra szolgál, hogy alárendelt erőforrásokat hozzon létre. Sikeres létrehozás esetén HTTP státuszként 201-t ad vissza, és a Válasz fejléccel egy linket a létrehozott erőforrásra az újonnan létrehozott erőforrással és a 201 HTTP státusszal.
  • PUT: Ez a metódus a képességek frissítésére szolgál. A PUT azonban akkor is használható erőforrás létrehozására, ha az erőforrás-azonosítót a kliens, és nem a szerver választja ki. Más szóval, ha a PUT egy olyan URI-hoz történik, amely nem létező erőforrásazonosító értékét tartalmazza. Sikeres frissítés esetén a PUT 200-at ad vissza (vagy 204-et, ha a testben nincs tartalom). Ha a PUT-ot létrehozásra használjuk, sikeres létrehozás esetén HTTP státuszként 201-et adunk vissza. A PUT nem biztonságos művelet, de idempotens.
  • PATCH: A PATCH-et a képességek módosítására használják. A PATCH kérés csak a változtatásokat tartalmazza az erőforráson, nem pedig a teljes erőforrást. Ez hasonlít a PUT-hoz, de a test egy olyan utasításkészletet tartalmazza, amely leírja, hogyan kell módosítani egy erőforrást a szerveren a meglévő verzió egy új verziójának előállításához. Ez azt jelenti, hogy a PATCH test nem csak az erőforrás egy módosított részét kell tartalmaznia, hanem valamilyen patch nyelvet, mint például a JSON Patch vagy az XML Patch. A PATCH nem biztonságos és nem idempotens.
  • DELETE: Ezt a módszert egy URI által azonosított erőforrás törlésére használják. Sikeres törlés esetén a HTTP státuszkódot 200 (OK) és a választestet adja vissza.

Todo alkalmazás REST API - szerver

Készíts egy egyszerű Todo alkalmazás szerveroldali REST API-t! Az alkalmazásnak lehetőséget kell biztosítania a felhasználók számára a teendők (todos) létrehozására, listázására, frissítésére és törlésére.

Az API-nak a következő funkcionalitást kell biztosítania:

  1. `GET /todos`: Az összes todo listázása JSON formátumban.
  2. `POST /todos`: Új todo létrehozása a kapott adatok alapján. A következő adatokat kell fogadnia: `title` (todo címe), `description` (todo leírása), `due_date` (todo határidője). A létrehozott todo objektumot kell visszaadnia JSON formátumban.
  3. `GET /todos/{id}`: Az adott azonosítójú todo részleteinek lekérése JSON formátumban.
  4. `PUT /todos/{id}`: Az adott azonosítójú todo frissítése a kapott adatok alapján. A következő adatok módosíthatók: `title`, `description`, `due_date`. A frissített todo objektumot kell visszaadnia JSON formátumban.
  5. `DELETE /todos/{id}`: Az adott azonosítójú todo törlése.

Minden endpointnak a megfelelő HTTP státuszkódot kell visszaadnia a kérések feldolgozása során, és a kliensekkel való kommunikáció JSON formátumban történjen.

Teszteléshez használhatsz API fejlesztőeszközöket, mint például a Postman vagy az Insomnia, hogy ellenőrizd az endpointok működését, valamint írj egységteszteket a különböző műveletekhez. Fontos, hogy az alkalmazásod a RESTful elveket kövesse és megfeleljen az elvárásoknak.

Todoo alkalmazás REST - kliens

Készítsen egy olyan HTML és JavaScript oldalt, amely képes kihasználni az előző feladatban létrehozott Todo alkalmazás REST API összes funkcióját. Az oldalnak lehetőséget kell biztosítania a felhasználók számára a teendők (todos) létrehozására, listázására, frissítésére és törlésére.

Az oldalnak tartalmaznia kell a következő elemeket és funkciókat:

  1. Todo listázása:

    • Az összes teendőt meg kell jeleníteni a felhasználónak, ha vannak.
    • Minden teendőnek meg kell jeleníteni a címét, leírását és határidejét.

  2. új todo létrehozása

    • Egy űrlap segítségével lehetőség van új teendő létrehozására.
    • A felhasználónak meg kell adnia a teendő címét, leírását és határidejét.

  3. Teendő frissítése:

    • Minden teendő mellett kell lennie egy szerkesztés gombnak, amely segítségével módosítható a teendő adatai.
    • A szerkesztés gomb megnyomására megjelenik egy űrlap, ahol a felhasználó módosíthatja a címet, leírást és határidőt.
    • A módosítás elküldése után a teendő adatai frissülniük kell az API-n keresztül.

  4. Teendő törlése:

    • Minden teendő mellett kell lennie egy törlés gombnak, amely segítségével törölhető a teendő az adatbázisból az API segítségével.

  5. Az oldalnak a felhasználói interakciókra reagálnia kell anélkül, hogy az oldalt újra kellene betölteni. A kommunikáció az API-val JavaScript segítségével AJAX hívásokkal történjen.

  6. Az elkészült oldalt kérjük a megadott API-hoz csatlakozva tesztelni, hogy minden funkció megfelelően működik-e.
